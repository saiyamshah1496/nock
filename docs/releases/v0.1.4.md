# v0.1.4 — Catalogue in sync-estate + R005 soften / R017 suppress

This release bumps all publishable `@nockhq/*` packages to 0.1.4 and ships the Phase‑1 governance catalogue in `sync-estate` (EstateSnapshot). The CLI now emits additive catalogue sections (`columns[]`, `constraints[]`, `indexes[]`) alongside table sizes and version metadata (plus table `relkind` and `replica_identity` signals). Omitted section keys indicate “catalogue absent” (fail‑closed for catalogue‑aware rules); present‑but‑empty arrays mean “synced; none found”.

Rule updates:
- R005 — SET NOT NULL without validated CHECK is softened via catalogue: yellow by default when the catalogue shows safety (already NOT NULL or validated CHECK); remains red on large tables when not justified.
- R017 — ADD UNIQUE/PRIMARY KEY without USING INDEX is suppressed when a matching valid/ready/immediate unique/primary index with equal, order‑sensitive `columns[]` exists in the catalogue. Fail‑closed on omitted catalogue; empty/mismatch/invalid do not suppress.

Docs and examples are updated to use:

```bash
npx @nockhq/cli@0.1.4 ...
```
