# v0.1.5 — R022/R023 catalogue consumers + R007 supporting‑index advisory

This release bumps all publishable `@nockhq/*` packages to 0.1.5 and extends the catalogue‑aware rules shipped in v0.1.4.

Highlights:
- R022 — VALIDATE CONSTRAINT on hot table
  - Yellow on ≥10k rows; red on ≥100k rows
  - Catalogue‑aware suppression when the matching constraint is already validated
- R023 — Invalid or not‑ready index on touched table
  - Default yellow when any `valid=false` or `ready=false` index exists on a table touched by the migration
  - Fail‑closed when the `indexes[]` section is omitted from the estate snapshot
- R007 — Foreign key
  - Existing behavior: red for `ADD FOREIGN KEY` without `NOT VALID` on large tables; remediate by `NOT VALID` then `VALIDATE`
  - New: extra yellow advisory when the FK’s child columns lack a supporting index (prefix/equal) in the catalogue

Background (from v0.1.4):
- `sync-estate` now captures a governance catalogue alongside sizes — additive sections `columns[]`, `constraints[]`, `indexes[]`.
- Catalogue‑aware consumers:
  - R005 softens to yellow when the catalogue shows safety (already NOT NULL or validated CHECK).
  - R017 suppresses when a matching valid/ready/immediate unique/primary index with equal, order‑sensitive `columns[]` exists.

Docs and examples are updated to use:
