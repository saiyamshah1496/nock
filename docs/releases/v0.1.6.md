# v0.1.6 — R008/R009 catalogue deepen

This release bumps all publishable `@nockhq/*` packages to 0.1.6 and deepens the governance catalogue rules:

- R008 — ALTER TYPE non-binary-coercible (catalogue-aware): soften only truly binary‑coercible varchar widens when `columns[]` are present — `varchar(n)→varchar(m≥n)` or `varchar(n)→text`. Omitted catalogue keeps the existing conservative behavior; lengthed `VARCHAR` without catalogue warns.
- R009 — DROP/RENAME (catalogue-aware): escalate when dropping PRIMARY KEY/UNIQUE that is the replica identity path (`tables[].replica_identity` = d/i); escalate when dropping a column that still appears in `constraints[].columns`/`indexes[].columns` with dependency‑aware remediation.

Design note: see `docs/design/026-catalogue-consumers-r008-r009.md`.

On your side:

- Upgrade to CLI 0.1.6+ and keep your workflow pins updated.
- Re‑run `sync-estate` (and any scheduled `--push-url` jobs) so hosted/file estates include the latest catalogue sections.

Example:

```bash
npx @nockhq/cli@0.1.6 ...
```
